# 1. Терминология O2P

## 1.1. Базовое различие миров

В O2P вводятся два фундаментальных множества:

```text
ΔIdea  — множество элементов мира идей
ΔThing — множество элементов мира вещей
```

Их предполагаемое отношение:

```text
ΔIdea ∩ ΔThing = ∅
```

Это означает:

- элементы `ΔIdea` — не вещи предметного мира;
- элементы `ΔThing` — не категории и образы мира идей;
- класс `Book` и конкретная книга `book123` имеют разную природу.

Но это не стандартная семантика OWL 2 DL. Это собственное базовое требование проекта O2P.

## 1.2. Термин «идея»

В O2P **идея** — элемент мира идей, задающий категорию, форму, тип, образ или способ организации вещей.

Примеры:

```text
Book
Person
Animal
Publication
RedThing
Process
```

В O2P идея — не конкретная вещь:

```text
Book ≠ конкретная книга
Person ≠ конкретный человек
```

Идея может определять множество вещей, которым она соответствует.

## 1.3. Термин «категория»

**Категория** — элемент мира идей, предназначенный для группировки или определения вещей мира вещей.

В O2P категория — это частный вид элемента `ΔIdea`.

Формально:

```text
Category ⊆ ΔIdea
```

Пример:

```text
Book ∈ Category
```

Однако в обычном OWL термин «категория» не является отдельной встроенной сущностью. Обычно он моделируется через `owl:Class`.

В O2P нужно различать:

| Термин | Значение в обычном OWL | Значение в O2P |
|---|---|---|
| Категория | Неформальный аналог класса | Элемент мира идей |
| Класс | Множество индивидов | Идея, задающая или описывающая категорию вещей |
| Тип | Класс, которому принадлежит индивид | Отношение между вещью и идеей |
| Концепт | Обычно неформальный термин | Обобщённый элемент мира идей |
| Форма | Философское понятие | Структура или образ, задающий свойства вещей |

## 1.4. Термин «класс»

В классическом OWL класс интерпретируется как множество индивидов:

```text
Cᴵ ⊆ Δᴵ
```

Например:

```text
Bookᴵ ⊆ Δᴵ
```

означает: интерпретация класса `Book` является подмножеством области индивидов.

В O2P это недостаточно точно. В O2P нужно различать:

```text
BookIdea — идея или категория «книга»
Bookᴵ     — множество вещей, соответствующих этой идее
```

То есть:

```text
BookIdea ∈ ΔIdea
Bookᴵ ⊆ ΔThing
```

Предпочтительная O2P-интерпретация:

```text
Идея Book задаёт класс вещей Bookᴵ.
```

Формально:

```text
ext(BookIdea) = Bookᴵ
```

где:

```text
ext — функция соответствия идеи множеству вещей
```

Таким образом:

```text
BookIdea — элемент мира идей
Bookᴵ     — множество вещей мира вещей, соответствующих BookIdea
```

Это принципиально отличается от стандартного OWL, где имя класса сразу интерпретируется как множество индивидов.

## 1.5. Термин «индивид»

**Индивид** (`individual`) — именованный или анонимный элемент области объектов, который не рассматривается как множество объектов.

В обычном OWL:

```text
:book123
```

может быть именованным индивидом:

```turtle
:book123 rdf:type :Book .
```

В O2P индивид — это элемент мира вещей:

```text
book123 ∈ ΔThing
```

Пример:

```text
book123 — конкретная книга
tolstoy  — конкретный человек
moscow   — конкретный город
```

Формально:

```text
book123 ∈ ΔThing
```

и, если книга соответствует идее `BookIdea`:

```text
book123 ∈ ext(BookIdea)
```

## 1.6. Различие терминов «индивид», «вещь» и «объект»

В O2P предлагаю использовать следующие различия:

| Термин | Значение в O2P |
|---|---|
| Вещь | Элемент мира вещей `ΔThing` |
| Индивид | Именованный элемент мира вещей |
| Объект предметной области | Вещь, рассматриваемая в модели |
| Экземпляр идеи | Вещь, связанная с элементом мира идей |
| RDF-объект | Третий компонент RDF-тройки |
| OWL individual | Именованный элемент, используемый в роли индивида OWL |
| Объект свойства | Значение, находящееся справа от предиката RDF-тройки |

Важно:

```text
индивид ≠ RDF-объект
```

Например:

```turtle
:book123 :hasColor "red" .
```

Здесь:

- `:book123` — RDF subject;
- `:hasColor` — RDF predicate;
- `"red"` — RDF object.

Но `"red"` — не обязательно индивид O2P. Это значение данных.

В RDF тройка состоит из субъекта, предиката и объекта. Объектом может быть IRI, blank node или literal. Поэтому термин «объект» в выражении «RDF object» нельзя автоматически понимать как объект мира вещей. [w3](https://www.w3.org/TR/rdf11-concepts/)

## 1.7. Термин «сущность»

В RDF **ресурс** — это то, что обозначается IRI или литералом. RDF допускает в качестве ресурсов физические объекты, документы, абстрактные понятия, числа и строки. В RDF Semantics термин `resource` близок к термину `entity`. [w3](https://www.w3.org/TR/rdf11-concepts/)

В OWL 2 **сущность** (`entity`) — именованный примитивный элемент онтологии, идентифицируемый IRI:

```text
Class
ObjectProperty
DataProperty
AnnotationProperty
NamedIndividual
Datatype
```

В O2P нужно различать:

| Термин | Смысл |
|---|---|
| RDF-ресурс | Общий элемент RDF-дискурса |
| OWL-сущность | Именованный элемент OWL-словаря |
| O2P-элемент | Элемент `ΔIdea` или `ΔThing` |
| IRI | Идентификатор, а не сам объект |
| Термин | Символ или имя, обозначающее сущность |
| Референт | То, что обозначается именем |

Пример:

```turtle
o2p:Book
```

Здесь:

```text
o2p:Book — IRI и имя
BookIdea — обозначаемый элемент мира идей
```

В обычном RDF один и тот же IRI может участвовать в разных позициях. В O2P нужно дополнительно зафиксировать, какую роль он играет.

## 1.8. Термин «тип»

В обычном RDF:

```turtle
x rdf:type C .
```

означает:

```text
x является экземпляром класса C
```

В O2P отказываемся от универсального `rdf:type` для фундаментального членства и вводим:

```turtle
x o2p:isInst C .
```

Смысл:

```text
x является экземпляром идеи или категории C
```

В O2P:

```text
book123 o2p:isInst BookIdea .
```

означает:

```text
book123 ∈ ext(BookIdea)
```

или в словесной форме:

```text
вещь book123 соответствует идее BookIdea
```

Термин «имеет тип» можно использовать как краткую форму, но нормативным отношением O2P будет:

```text
o2p:isInst
```

## 1.9. Термин «экземпляр»

Термин «экземпляр» в O2P нужно использовать только с уточнением:

```text
экземпляр идеи
экземпляр категории
экземпляр класса вещей
экземпляр RDF-класса
экземпляр метакласса
```

В O2P рекомендуется:

```text
вещь book123 является экземпляром идеи BookIdea
```

а не:

```text
book123 — экземпляр Book
```

без уточнения.

Причина:

```text
BookIdea ∈ ΔIdea
book123 ∈ ΔThing
```

Это элементы разных миров. Поэтому `o2p:isInst` в O2P — не симметричное отношение между элементами одного типа.

## 1.10. Термины `Class`, `Individual`, `ObjectProperty`

### `Class`

В OWL `Class` — сущность, обозначающая класс.

В O2P желательно разделить:

```text
o2p:Class — класс элементов мира идей
o2p:Thing — класс элементов мира вещей
```

Но имена `o2p:Class` и `o2p:Thing` — это уже элементы самой метамодели O2P. Поэтому возникает рекурсивный вопрос: к какому миру относятся они?

Для O2P следует ввести метауровень:

```text
MetaO2P — уровень описания самой метамодели
```

Тогда:

```text
o2p:Class — метаязык или описание множества идей
o2p:Thing — метаязык или описание множества вещей
```

### `Individual`

В OWL `NamedIndividual` — именованная сущность, используемая как индивид.

В O2P:

```text
o2p:book123
```

имеет роль:

```text
ThingIndividual
```

и обозначает элемент:

```text
book123 ∈ ΔThing
```

### `ObjectProperty`

В OWL `ObjectProperty` связывает индивидов с индивидами:

```text
x P y
```

В O2P это понятие нужно разделить минимум на три сорта:

```text
o2p:IIProperty — Idea–Idea
o2p:ITProperty — Idea–Thing
o2p:TTProperty — Thing–Thing
```

Например:

```text
o2p:isSubC — Idea–Idea
o2p:isInst — Thing–Idea
o2p:hasAuthor — Thing–Thing
o2p:hasColor — Thing–Data
```

В записи `IT` направление следует читать как:

```text
субъект — Idea
объект — Thing
```

Для `o2p:isInst` естественнее использовать обозначение:

```text
Thing–Idea
```

поскольку вещь является экземпляром идеи:

```text
Thing → Idea
```

# 2. Задача и концепция O2P

## 2.1. Философская постановка

Исходная идея:

```text
всё существующее различается как:
1. мир идей;
2. мир вещей.
```

В O2P это формализуется как два непересекающихся сорта:

```text
Idea — элемент мира идей
Thing — элемент мира вещей
```

Их области:

```text
ΔIdea
ΔThing
```

Базовое ограничение:

```text
ΔIdea ∩ ΔThing = ∅
```

## 2.2. Мир идей

Мир идей содержит:

```text
категории
классы
типы
концепты
формы
образы
отношения между категориями
ограничения и определения
```

Примеры:

```text
Book
Person
Animal
Publication
Red
Process
```

В O2P эти элементы не являются конкретными физическими вещами.

## 2.3. Мир вещей

Мир вещей содержит:

```text
конкретные объекты
события
процессы
состояния
наблюдаемые явления
документы
физические или абстрактные индивидуальные объекты
```

Примеры:

```text
book123
tolstoy
moscow
process_001
redBook123
```

## 2.4. Отношение воплощения

Основное отношение между мирами:

```turtle
o2p:book123 o2p:isInst o2p:Book .
```

Смысл:

```text
вещь book123 является экземпляром идеи Book
```

Формально:

```text
book123 ∈ ext(Book)
```

где:

```text
ext(Book) ⊆ ΔThing
```

или:

```text
ext: ΔIdea → ℘(ΔThing)
```

Это означает: каждой идее сопоставляется множество вещей, которые ей соответствуют.

## 2.5. Отношение подкатегории

```turtle
o2p:Book o2p:isSubC o2p:Publication .
```

Смысл:

```text
идея Book является подклассом идеи Publication
```

Формально:

```text
ext(Book) ⊆ ext(Publication)
```

Это отношение только между элементами мира идей:

```text
Idea → Idea
```

## 2.6. Свойства и методы

Для каждой идеи можно задать допустимые характеристики и операции:

```text
Book
├── hasTitle
├── hasAuthor
├── hasColor
├── hasPageCount
└── open()
```

Но здесь нужно различать:

```text
свойство идеи
значение свойства у вещи
метод идеи
реализация метода у вещи
```

Например:

```turtle
o2p:Book o2p:hasProperty o2p:hasColor .
o2p:book123 o2p:hasColor o2p:Red .
```

Смысл:

```text
идея Book предусматривает свойство hasColor
вещь book123 имеет значение Red
```

В O2P лучше не задавать это одной и той же безтиповой связью.

# 3. Почему обычный OWL 2 DL не выражает O2P полностью

## 3.1. Семантика OWL 2 DL

В Direct Semantics OWL 2 DL есть:

```text
ΔI — область объектов
ΔD — область значений данных
```

Класс интерпретируется как подмножество `ΔI`:

```text
Cᴵ ⊆ ΔI
```

Индивид интерпретируется как элемент `ΔI`:

```text
aᴵ ∈ ΔI
```

ObjectProperty интерпретируется как отношение:

```text
Pᴼᴾ ⊆ ΔI × ΔI
```

DataProperty интерпретируется как отношение:

```text
Pᴰᴾ ⊆ ΔI × ΔD
```

В стандартной Direct Semantics нет отдельного корневого домена:

```text
ΔIdea
```

Поэтому OWL 2 DL не выражает напрямую:

```text
ΔIdea ∩ ΔThing = ∅
```

если под `ΔIdea` и `ΔThing` понимаются фундаментально разные типы объектов.

## 3.2. Почему `owl:Thing` не является миром вещей O2P

В OWL 2:

```text
owl:Thingᴵ = ΔI
```

То есть `owl:Thing` — универсальный класс области объектов.

Но O2P хочет:

```text
ΔThing — мир вещей
ΔIdea  — мир идей
```

В OWL 2 DL нет автоматического соответствия:

```text
owl:Thing = ΔThing
owl:Class = ΔIdea
```

Особенно проблематично, что `owl:Class` в RDF-представлении — это специальный vocabulary term, а не универсальный семантический домен всех классов.

## 3.3. Почему нельзя объявить `owl:Class` и `owl:Thing` непересекающимися

Можно написать:

```turtle
owl:Class owl:disjointWith owl:Thing .
```

Но `owl:disjointWith` означает непересечение интерпретаций двух классов:

```text
Cᴵ ∩ Dᴵ = ∅
```

При этом:

```text
owl:Thingᴵ = ΔI
```

и любой класс является подмножеством `ΔI`:

```text
owl:Classᴵ ⊆ ΔI
```

Тогда утверждение о непересечении даёт:

```text
owl:Classᴵ ∩ ΔI = ∅
```

Но одновременно:

```text
owl:Classᴵ ⊆ ΔI
```

Следовательно:

```text
owl:Classᴵ = ∅
```

То есть вы не отделяете мир идей от мира вещей, а делаете интерпретацию `owl:Class` пустой.

Проблема в том, что:

```text
owl:disjointWith
```

разделяет множества индивидов одного object domain, а не вводит два разных типа семантических доменов.

## 3.4. Что такое «punning» (разноименное использование)

**Punning (разноименное использование одного имени)** — это ситуация, когда один и тот же IRI используется в нескольких OWL-ролях.

Например:

```turtle
:Eagle rdf:type owl:Class .
:Eagle rdf:type :Species .
```

В одном контексте `:Eagle` используется как класс, а в другом — как индивид класса `:Species`.

В OWL 2 DL это не означает, что класс и индивид отождествлены.

Условно это можно представить как два независимых обозначения:

```text
Eagle_as_Class
Eagle_as_Individual
```

Одинаковый IRI используется как имя, но семантические роли различны.

Punning позволяет:

```text
Eagleᴄ — класс орлов
Eagleᴵ — индивидуальный объект, представляющий вид Eagle
```

Но из:

```text
:Eagle rdf:type owl:Class .
:Eagle rdf:type :Species .
```

не следует:

```text
Eagleᴄ = Eagleᴵ
```

и не следует, что множество экземпляров класса `Eagle` совпадает с индивидом `Eagle`.

Для O2P это нежелательно, если требуется строгая прозрачность двух миров. Поэтому в O2P лучше либо:

```text
не использовать один IRI в разных сортах
```

либо явно вводить сортированные имена:

```text
o2p:idea/Book
o2p:thing/book123
```

## 3.5. OWL 2 Full

OWL 2 Full более свободно допускает метамоделирование:

```text
классы могут выступать как ресурсы
ресурсы могут быть классами
классы могут быть членами других классов
```

Это ближе к философской идее мира идей как объектов более высокого уровня.

Но OWL 2 Full не вводит автоматически:

```text
ΔIdea
ΔThing
```

и не гарантирует, что они непересекаются.

Кроме того:

- нет общей гарантии разрешимости;
- сложнее предсказывать выводы;
- нет строгой типизации отношений;
- смешиваются логический и метамодельный уровни.

Поэтому OWL 2 Full даёт больше свободы, но не решает O2P как формальную двухсортную семантику.

## 3.6. Сравнение подходов

| Подход | Два сорта Idea/Thing | Строгая типизация | Метамоделирование | Reasoning | Подходит O2P |
|---|---:|---:|---:|---:|---:|
| RDF/RDFS | Нет | Нет | Свободное | Ограниченное | Только как база |
| OWL 2 DL | Нет напрямую | Да | Ограниченное | Сильное | Частично |
| OWL 2 Full | Не гарантирует | Нет | Свободное | Непредсказуемее | Частично |
| SHACL | Не задаёт семантические домены | Проверка форм | Да | Валидация | Как слой ограничений |
| ShEx | Не задаёт семантические домены | Проверка форм | Ограниченно | Валидация | Как слой форм |
| Двухсортная логика | Да | Да | Да | Зависит от логики | Наиболее естественно |
| Common Logic | Возможно через сорта | Да | Да | Зависит от реализации | Возможный фундамент |
| O2P-метамодель над RDF | Да | Да | Контролируемое | Через OWL/правила | Наиболее практично |

SHACL предназначен для проверки RDF-графов по заданным условиям, а не для определения фундаментальной модели двух миров. Поэтому SHACL полезен в O2P как язык валидации, но не как базовая логика проекта. [w3](https://www.w3.org/TR/shacl/)

# 4. Отказ от универсального `rdf:type`

## 4.1. Мотивация

В O2P предлагается не использовать `rdf:type` как основное отношение членства.

Вместо этого вводятся специализированные предикаты:

```turtle
o2p:isInst
o2p:isSubC
o2p:hasProperty
o2p:hasValue
```

Это помогает разделить:

```text
вещь является экземпляром идеи
идея является подклассом идеи
вещь имеет значение свойства
идея задаёт допустимое свойство
```

## 4.2. `o2p:isInst`

```turtle
o2p:book123 o2p:isInst o2p:Book .
```

Смысл:

```text
Thing → Idea
```

Формально:

```text
o2p:isInst ⊆ ΔThing × ΔIdea
```

То есть:

```text
x o2p:isInst y
```

разрешается только если:

```text
x ∈ ΔThing
y ∈ ΔIdea
```

Это существенно отличается от универсального RDF:

```turtle
x rdf:type C .
```

## 4.3. `o2p:isSubC`

```turtle
o2p:Book o2p:isSubC o2p:Publication .
```

Смысл:

```text
Book — подкатегория Publication
```

Тип связи:

```text
Idea → Idea
```

Формально:

```text
o2p:isSubC ⊆ ΔIdea × ΔIdea
```

Основное ограничение:

```text
x o2p:isSubC y
```

допустимо только при:

```text
x ∈ ΔIdea
y ∈ ΔIdea
```

Семантическое условие:

```text
ext(x) ⊆ ext(y)
```

## 4.4. Предикаты по типам концов

В O2P следует классифицировать отношения по сортам субъекта и объекта.

| Тип | Направление | Пример | Назначение |
|---|---|---|---|
| Idea–Idea | ΔIdea → ΔIdea | `isSubC` | отношения категорий |
| Thing–Idea | ΔThing → ΔIdea | `isInst` | соответствие вещи идее |
| Idea–Thing | ΔIdea → ΔThing | `hasPrototype` | связь идеи с образцом вещи |
| Thing–Thing | ΔThing → ΔThing | `hasAuthor` | отношения вещей |
| Thing–Data | ΔThing → ΔData | `hasColorValue` | значение свойства |
| Idea–Data | ΔIdea → ΔData | `hasLabel` | метаданные идеи |
| Meta–Idea | метауровень → ΔIdea | `describes` | описание типов идей |
| Meta–Thing | метауровень → ΔThing | `describes` | описание типов вещей |

## 4.5. Предикаты Idea–Idea

Примеры:

```turtle
o2p:Book o2p:isSubC o2p:Publication .
o2p:Book o2p:isEquivalentTo o2p:Volume .
o2p:Book o2p:isDisjointFrom o2p:Stone .
o2p:Book o2p:hasProperty o2p:hasColor .
o2p:Book o2p:hasMethod o2p:open .
```

Все субъекты и объекты должны быть идеями:

```text
Idea → Idea
```

Предикаты:

```text
o2p:isSubC
o2p:isEquivalentTo
o2p:isDisjointFrom
o2p:hasProperty
o2p:hasMethod
o2p:constrains
o2p:defines
o2p:generalizes
```

## 4.6. Предикаты Thing–Idea

Главный пример:

```turtle
o2p:book123 o2p:isInst o2p:Book .
```

Другие возможные отношения:

```text
o2p:conformsTo
o2p:realizes
o2p:manifests
o2p:classifiedBy
o2p:hasForm
```

Но нужно различать:

```text
isInst — членство или соответствие категории
realizes — реализация идеи
manifests — проявление идеи
classifiedBy — результат классификации
```

Не следует автоматически считать их синонимами.

## 4.7. Предикаты Thing–Thing

Примеры:

```turtle
o2p:book123 o2p:hasAuthor o2p:tolstoy .
o2p:book123 o2p:locatedIn o2p:library1 .
o2p:process1 o2p:uses o2p:machine1 .
```

Тип:

```text
Thing → Thing
```

Эти отношения соответствуют наиболее привычным object properties OWL.

## 4.8. Предикаты Thing–Data

Например:

```turtle
o2p:book123 o2p:hasPageCount "1225"^^xsd:integer .
o2p:book123 o2p:hasColorValue "red" .
```

Тип:

```text
Thing → Data
```

В O2P значения данных лучше отделить от вещей:

```text
ΔData
```

Итоговая базовая модель:

```text
ΔIdea
ΔThing
ΔData
```

с условиями:

```text
ΔIdea ∩ ΔThing = ∅
ΔIdea ∩ ΔData = ∅
ΔThing ∩ ΔData = ∅
```

# 5. Расширение ABox и TBox

## 5.1. Классическая терминология

В Description Logic:

```text
TBox — терминологические аксиомы
ABox — утверждения о конкретных индивидах
RBox — утверждения о ролях или свойствах
```

### TBox

Описывает классы:

```text
Book ⊑ Publication
Person ⊑ Agent
```

### ABox

Описывает индивидов:

```text
book123 : Book
tolstoy : Person
```

### RBox

Описывает свойства:

```text
hasAuthor(book123, tolstoy)
```

## 5.2. Почему стандартного разделения недостаточно для O2P

В O2P нужно различать не только TBox и ABox, но и типы миров:

```text
IdeaBox — утверждения об идеях
ThingBox — утверждения о вещах
BridgeBox — связи между идеями и вещами
DataBox — связи с данными
MetaBox — утверждения о самой метамодели
```

Предлагаемая структура:

```text
O2P ontology
├── IdeaBox
├── ThingBox
├── BridgeBox
├── IdeaRelationBox
├── ThingRelationBox
├── DataBox
└── MetaBox
```

### IdeaBox

```turtle
o2p:Book o2p:isSubC o2p:Publication .
```

### ThingBox

```turtle
o2p:book123 o2p:hasAuthor o2p:tolstoy .
```

### BridgeBox

```turtle
o2p:book123 o2p:isInst o2p:Book .
```

### DataBox

```turtle
o2p:book123 o2p:hasColorValue "red" .
```

### MetaBox

```turtle
o2p:isInst o2p:hasDomain o2p:Thing .
o2p:isInst o2p:hasRange o2p:Idea .
```

## 5.3. O2P-предикаты как типизированные отношения

Вместо одного универсального `rdf:type` вводится явная типизация:

```turtle
o2p:isInst o2p:relationKind o2p:ThingIdea .
o2p:isSubC o2p:relationKind o2p:IdeaIdea .
o2p:hasAuthor o2p:relationKind o2p:ThingThing .
```

Или:

```turtle
o2p:isInst o2p:hasSourceSort o2p:Thing .
o2p:isInst o2p:hasTargetSort o2p:Idea .

o2p:isSubC o2p:hasSourceSort o2p:Idea .
o2p:isSubC o2p:hasTargetSort o2p:Idea .
```

Для GitHub-файла можно использовать:

```turtle
@prefix o2p: <https://example.org/o2p#> .

o2p:isInst
    o2p:hasSourceSort o2p:Thing ;
    o2p:hasTargetSort o2p:Idea .

o2p:isSubC
    o2p:hasSourceSort o2p:Idea ;
    o2p:hasTargetSort o2p:Idea .
```

## 5.4. Проверка домена и диапазона

В SHACL можно проверять, что `o2p:isSubC` связывает только идеи:

```turtle
o2p:IdeaIdeaShape
    a sh:NodeShape ;
    sh:targetSubjectsOf o2p:isSubC ;
    sh:property [
        sh:path o2p:isSubC ;
        sh:class o2p:Idea ;
    ] .
```

А для `o2p:isInst`:

```turtle
o2p:ThingIdeaShape
    a sh:NodeShape ;
    sh:targetSubjectsOf o2p:isInst ;
    sh:class o2p:Thing ;
    sh:property [
        sh:path o2p:isInst ;
        sh:class o2p:Idea ;
    ] .
```

Это не создаёт новую семантику OWL, но позволяет валидировать O2P-граф. SHACL по своему назначению является языком проверки RDF-графов по условиям и ограничениям. [w3](https://www.w3.org/TR/shacl/)

# 6. Модель свойств и методов

## 6.1. Свойство идеи

Идея `Book` задаёт возможность иметь цвет:

```turtle
o2p:Book o2p:hasProperty o2p:hasColor .
```

Это утверждение Idea–Idea:

```text
Book — Idea
hasColor — Idea или описание свойства
```

Можно определить свойство как самостоятельный элемент:

```turtle
o2p:hasColor o2p:propertyKind o2p:ThingThing .
```

Если цвет является отдельной сущностью мира идей:

```turtle
o2p:Color o2p:isSubC o2p:AttributeValue .
```

## 6.2. Значение свойства вещи

```turtle
o2p:book123 o2p:hasColor o2p:Red .
```

Здесь возможны два варианта.

### Цвет как идея

```text
Red ∈ ΔIdea
```

Тогда:

```text
Thing → Idea
```

### Цвет как значение данных

```turtle
o2p:book123 o2p:hasColorValue "red" .
```

Тогда:

```text
Thing → Data
```

Нужно заранее выбрать модель:

| Модель | Пример | Когда использовать |
|---|---|---|
| Значение как идея | `book123 hasColor Red` | цвет — концепт или категория |
| Значение как literal | `book123 hasColorValue "red"` | цвет — простое значение |
| Значение как вещь | `book123 hasColorInstance redPigment1` | цвет — физический объект или образец |

## 6.3. Метод идеи

Метод лучше рассматривать как элемент мира идей:

```turtle
o2p:Book o2p:hasMethod o2p:open .
```

Здесь:

```text
Book — Idea
open — MethodIdea
```

Реализация метода конкретной вещью может быть представлена:

```turtle
o2p:book123 o2p:realizes o2p:open .
```

или отдельным процессом:

```turtle
o2p:openingProcess1 o2p:implements o2p:open .
o2p:openingProcess1 o2p:actsOn o2p:book123 .
```

OWL сам по себе не является языком объектно-ориентированных методов. Поэтому `hasMethod` будет доменным расширением O2P, а не стандартной конструкцией OWL.

# 8. Нужно ли использовать `owl:Class` или `o2p:Class`

## 8.1. Вариант с `owl:Class`

Можно записать:

```turtle
o2p:Book a owl:Class .
```

Но тогда `o2p:Book` используется в стандартной OWL-роли класса, то есть интерпретируется как множество индивидов `ΔI`.

Это не соответствует полностью O2P, где `Book` должен быть элементом `ΔIdea`.

## 8.2. Вариант с `o2p:Idea`

Предпочтительнее:

```turtle
o2p:Book a o2p:Idea .
o2p:book123 a o2p:Thing .
o2p:book123 o2p:isInst o2p:Book .
```

Это явно говорит:

```text
Book — элемент мира идей
book123 — элемент мира вещей
```

При этом `o2p:Idea` и `o2p:Thing` будут прикладными OWL-классами общей RDF/OWL-области, поэтому полная двухсортность всё ещё не выражена стандартной OWL-семантикой. Но O2P-сортировка становится явной и проверяемой.

## 8.3. Рекомендуемый отказ от прямой семантики `owl:Class`

В ядре O2P рекомендую:

```text
не использовать owl:Class для всех элементов мира идей;
использовать o2p:Idea и специализированные подклассы;
использовать OWL 2 DL как средство ограничения и reasoning внутри модели;
зафиксировать двухсортные правила O2P отдельно.
```

Пример:

```turtle
o2p:Idea a owl:Class .
o2p:Thing a owl:Class .

o2p:Category rdfs:subClassOf o2p:Idea .
o2p:PropertyIdea rdfs:subClassOf o2p:Idea .
o2p:MethodIdea rdfs:subClassOf o2p:Idea .

o2p:Individual rdfs:subClassOf o2p:Thing .
o2p:Event rdfs:subClassOf o2p:Thing .
o2p:Process rdfs:subClassOf o2p:Thing .
```

# 9. Как формализовать два мира строго

Если требуется строгая семантика, лучше определить O2P как **многосортную логическую надстройку**.

## 9.1. Сорта

```text
Sort Idea
Sort Thing
Sort Data
Sort Relation
```

## 9.2. Предикаты

```text
isInst: Thing × Idea → Truth
isSubC: Idea × Idea → Truth
hasProperty: Idea × Idea → Truth
hasMethod: Idea × Idea → Truth
hasAuthor: Thing × Thing → Truth
hasValue: Thing × Data → Truth
```

## 9.3. Аксиомы сортировки

```text
isInst(x, y) → Thing(x) ∧ Idea(y)
isSubC(x, y) → Idea(x) ∧ Idea(y)
hasAuthor(x, y) → Thing(x) ∧ Thing(y)
hasValue(x, y) → Thing(x) ∧ Data(y)
```

## 9.4. Аксиомы наследования

```text
isSubC(A, B) ∧ isInst(x, A) → isInst(x, B)
```

В словесной форме:

```text
если A является подклассом B,
а x является экземпляром A,
то x является экземпляром B.
```

## 9.5. Аксиомы свойств

```text
hasProperty(A, P) ∧ isInst(x, A) → mayHave(x, P)
```

Это уже не стандартная OWL-аксиома, а O2P-правило.

# 10. Итоговая рекомендация по технологии

## 10.1. Что использовать в O2P

Рекомендованная архитектура:

```text
RDF 1.1
    как графовая модель хранения

O2P vocabulary
    как явная типизация миров и отношений

OWL 2 DL
    как средство описания локальных классов,
    иерархий и ограничений

SHACL
    как средство проверки сортов,
    доменов и диапазонов отношений

SPARQL
    как средство запросов и преобразований

O2P rules
    как явная двухсортная семантика
```

## 10.2. Что не следует использовать как единственную основу

Не следует пытаться получить весь O2P только через:

```text
owl:Class
owl:Thing
rdf:type
owl:disjointWith
```

Причины:

1. `owl:Thing` — универсальный класс OWL object domain, а не специальный мир вещей O2P.
2. `owl:Class` — vocabulary term OWL, а не отдельный корневой домен идей.
3. `owl:disjointWith` разделяет классы внутри одной области, а не разные семантические домены.
4. `rdf:type` не различает автоматически Thing–Idea и Idea–Idea.
5. punning допускает одинаковый IRI в нескольких ролях, но не отождествляет эти роли.
6. OWL 2 DL не является многосортной логикой с доменами `ΔIdea` и `ΔThing`.
7. OWL 2 Full свободнее, но не даёт строгой и вычислимо контролируемой двухсортности.

## 10.3. Итоговая концепция O2P

```text
O2P — это двухсортная онтологическая метамодель,
в которой:

1. ΔIdea содержит категории, классы, типы, концепты,
   формы, свойства и методы.

2. ΔThing содержит индивиды, объекты, события,
   процессы и состояния.

3. ΔData содержит значения данных.

4. ΔIdea ∩ ΔThing = ∅.

5. o2p:isInst связывает Thing с Idea.

6. o2p:isSubC связывает Idea с Idea.

7. o2p:hasProperty связывает Idea с Idea.

8. o2p:hasAuthor и аналогичные свойства связывают Thing с Thing.

9. o2p:hasValue связывает Thing с Data.

10. OWL 2 DL используется как ограниченный логический
    слой, но не как полная семантика двух миров.

11. SHACL используется для проверки сортов и допустимых связей.

12. При необходимости O2P-правила реализуются
    средствами многосортной логики, SHACL Rules или SPARQL.
```

Главный практический результат:

```turtle
o2p:Book a o2p:Idea .
o2p:book123 a o2p:Thing .

o2p:book123 o2p:isInst o2p:Book .
o2p:Book o2p:isSubC o2p:Publication .

o2p:Book o2p:hasProperty o2p:hasColor .
o2p:book123 o2p:hasColorValue "red" .
```

Читается так:

```text
Book — идея или категория мира идей.
book123 — вещь мира вещей.
book123 является экземпляром идеи Book.
Book является подкатегорией Publication.
Идея Book предусматривает свойство hasColor.
Вещь book123 имеет значение цвета red.
```

Именно такая схема наиболее близка к цели O2P: не просто использовать OWL-классы и индивиды, а явно разделить **идеи как формы классификации** и **вещи как элементы моделируемого мира**. RDF даёт графовую основу, OWL 2 DL — логические ограничения, SHACL — проверку структуры, а собственная O2P-семантика — строгое разделение сортов и смысл отношений. [w3](https://www.w3.org/TR/rdf11-concepts/)

```turtle
o2p:book123
```

не используется, поскольку O2P не должно содержать конкретную книгу.

# 2. Основные миры O2P

В O2P различаются:

```text
мир идей
мир вещей
мир данных
```

В терминах множеств:

```text
ΔIdea  — множество элементов мира идей
ΔThing — множество элементов мира вещей
ΔData  — множество значений данных
```

Предполагается:

```text
ΔIdea ∩ ΔThing = ∅
ΔIdea ∩ ΔData = ∅
ΔThing ∩ ΔData = ∅
```

Эти обозначения являются собственной семантикой O2P. Они не являются готовыми встроенными доменами OWL 2 DL.

## 2.1. Мир идей

Мир идей содержит:

```text
категории
классы
типы
концепты
формы
образы
описания свойств
описания методов
отношения между идеями
```

Примеры терминов O2P:

```turtle
o2p:Book
o2p:Person
o2p:Publication
o2p:Color
o2p:hasColor
o2p:hasAuthor
o2p:open
```

Это не конкретные книги, люди или значения цвета.

## 2.2. Мир вещей

Мир вещей содержит конкретные объекты предметной области:

```turtle
ex:alice
ex:bob
ex:book123
ex:library1
```

Эти ресурсы находятся в пространстве `ex:`, а не в `o2p:`.

## 2.3. Мир данных

Мир данных содержит литеральные значения:

```turtle
"red"
"white"
42
"1980-01-01"^^xsd:date
```

Литерал в RDF может быть только объектом RDF-тройки. RDF-тройка состоит из субъекта, предиката и объекта; объект может быть IRI, blank node или литералом. [w3](https://www.w3.org/TR/2013/CR-rdf11-concepts-20131105/)

В O2P следует различать:

```text
ΔThing — объекты предметной области
ΔData  — значения данных
```

Например:

```turtle
ex:book123 o2p:hasColorValue "red" .
```

Здесь:

```text
ex:book123 ∈ ΔThing
"red" ∈ ΔData
```

# 3. Главные термины O2P

## 3.1. Идея

**Идея** — элемент мира идей, задающий категорию, форму, тип, образ или иной способ классификации вещей.

Примеры:

```turtle
o2p:Book
o2p:Person
o2p:Publication
```

В O2P:

```text
o2p:Book ∈ ΔIdea
```

## 3.2. Категория

**Категория** — идея, предназначенная для группировки или классификации вещей.

В O2P:

```text
Category ⊆ ΔIdea
```

Например:

```turtle
o2p:Book
```

может быть категорией вещей-книг.

Важно: «категория» не является встроенной сущностью OWL. В O2P это специальный термин доменной метамодели.

## 3.3. Класс

**Класс** — идея, задающая множество вещей, соответствующих этой идее.

В O2P:

```text
o2p:Book ∈ ΔIdea
```

а множество вещей, соответствующих этой идее, обозначается:

```text
ext(o2p:Book) ⊆ ΔThing
```

Здесь `ext` означает «множество соответствующих объектов», или экстенсионал идеи.

Например:

```text
ex:book123 ∈ ext(o2p:Book)
```

Класс в O2P не должен автоматически отождествляться с множеством вещей. Нужно различать:

```text
o2p:Book      — идея или класс
ext(o2p:Book) — множество вещей, соответствующих этой идее
ex:book123    — конкретная вещь
```

## 3.4. Индивид

**Индивид** — конкретный именованный элемент мира вещей.

Примеры:

```turtle
ex:alice
ex:bob
ex:book123
```

В O2P:

```text
ex:alice ∈ ΔThing
ex:bob ∈ ΔThing
ex:book123 ∈ ΔThing
```

Индивид не является множеством и не является идеей.

## 3.5. Вещь

**Вещь** — элемент мира вещей, независимо от того, имеет ли он имя.

В O2P:

```text
Thing ⊆ ΔThing
```

Индивид — именованная вещь:

```text
ex:alice — именованная вещь
```

Можно также использовать анонимные вещи, представленные blank node, но для примеров O2P лучше применять IRI из пространства `ex:`.

## 3.6. Объект

Термин «объект» необходимо уточнять.

### Объект мира вещей

```text
ex:alice
ex:book123
```

Это элементы `ΔThing`.

### RDF-объект

В RDF объект — третий компонент RDF-тройки:

```turtle
ex:alice o2p:knows ex:bob .
```

Здесь:

```text
ex:alice — субъект
o2p:knows — предикат
ex:bob — RDF-объект
```

Но `ex:bob` одновременно является вещью мира вещей.

В другом примере:

```turtle
ex:book123 o2p:hasColorValue "red" .
```

`"red"` — RDF-объект, но это значение данных, а не вещь `ΔThing`.

Поэтому:

```text
RDF object ≠ обязательно O2P Thing
```

## 3.7. Сущность

**Сущность** (`entity`) — именованный элемент модели, идентифицируемый IRI.

В OWL к сущностям относятся:

```text
Class
ObjectProperty
DataProperty
AnnotationProperty
NamedIndividual
Datatype
```

В O2P термин «сущность» должен применяться осторожно:

| Термин | Значение |
|---|---|
| RDF-ресурс | То, что обозначено IRI, blank node или literal |
| OWL-сущность | Именованный элемент OWL-словаря |
| O2P-идея | Именованный элемент `ΔIdea` |
| O2P-вещь | Именованный элемент `ΔThing` |
| O2P-предикат | Именованный элемент набора отношений |
| IRI | Имя или идентификатор, а не сам обозначаемый объект |

Например:

```turtle
o2p:Book
```

— IRI и имя термина.

```turtle
ex:book123
```

— IRI и имя конкретного индивида.

## 3.8. Предикат

В RDF **предикат** — второй компонент тройки и обязательно IRI:

```turtle
subject predicate object
```

В O2P предикат — именованное отношение, описанное в пространстве `o2p:`.

Например:

```turtle
o2p:isInst
o2p:isSubC
o2p:hasAuthor
o2p:hasColorValue
```

Предикат не является автоматически вещью или идеей. Он относится к третьей категории:

```text
множество отношений O2P
```

В расширенной семантике O2P:

```text
ΔRelation — множество отношений
```

При этом каждый предикат имеет сигнатуру:

```text
o2p:isInst   : ΔThing × ΔIdea
o2p:isSubC   : ΔIdea × ΔIdea
o2p:hasAuthor: ΔThing × ΔThing
o2p:hasColorValue: ΔThing × ΔData
```

## 3.9. Тип

В O2P термин «тип» не должен выражаться универсальным `rdf:type`.

Вместо этого используются конкретные отношения:

```text
o2p:isInst — соответствие вещи идее
o2p:isSubC — отношение подкатегории между идеями
```

Например:

```turtle
ex:alice o2p:isInst o2p:Person .
```

Смысл:

```text
вещь ex:alice соответствует идее o2p:Person
```

# 4. Отказ от `rdf:type`

В O2P не используем `rdf:type` для утверждений ядра модели.

Вместо:

```turtle
ex:alice rdf:type o2p:Person .
```

пишем:

```turtle
ex:alice o2p:isInst o2p:Person .
```

Вместо:

```turtle
o2p:Book rdf:type owl:Class .
```

в O2P пишем:

```turtle
o2p:Book o2p:belongsToWorld o2p:IdeaWorld .
```

Вместо:

```turtle
ex:alice rdf:type o2p:Thing .
```

пишем:

```turtle
ex:alice o2p:belongsToWorld o2p:ThingWorld .
```

Таким образом, принадлежность к миру выражается не через RDF-тип, а через выделенный O2P-предикат.

# 5. Предикаты принадлежности к мирам

Вводятся два специальных термина миров:

```turtle
o2p:IdeaWorld
o2p:ThingWorld
o2p:DataWorld
```

И два варианта обозначения принадлежности.

## 5.1. Универсальный предикат миров

```turtle
o2p:belongsToWorld
```

Примеры:

```turtle
o2p:Book o2p:belongsToWorld o2p:IdeaWorld .
ex:alice o2p:belongsToWorld o2p:ThingWorld .
"red" o2p:belongsToWorld o2p:DataWorld .
```

Но последний вариант с литералом требует осторожности: литералы нельзя использовать субъектами RDF-троек. Поэтому принадлежность литералов к `DataWorld` обычно задаётся аксиомой модели, а не отдельной тройкой с литералом в субъекте.

## 5.2. Раздельные предикаты

Более строго:

```turtle
o2p:isIdea
o2p:isThing
o2p:isDataValue
```

Примеры для именованных ресурсов:

```turtle
o2p:Book o2p:isIdea o2p:IdeaWorld .
ex:alice o2p:isThing o2p:ThingWorld .
```

Однако такое именование несколько неестественно: `isIdea` связывает ресурс с миром, а не просто сообщает его тип.

Предпочтительный вариант:

```turtle
o2p:belongsToWorld
```

с объектом-идентификатором мира:

```turtle
o2p:Book o2p:belongsToWorld o2p:IdeaWorld .
ex:alice o2p:belongsToWorld o2p:ThingWorld .
```

# 6. Формальная сигнатура O2P

В O2P вводятся следующие области:

```text
ΔIdea
ΔThing
ΔData
ΔRelation
```

Они попарно не пересекаются:

```text
ΔIdea ∩ ΔThing = ∅
ΔIdea ∩ ΔData = ∅
ΔThing ∩ ΔData = ∅
ΔRelation ∩ ΔIdea = ∅
ΔRelation ∩ ΔThing = ∅
ΔRelation ∩ ΔData = ∅
```

## 6.1. Именованные идеи

```text
o2p:Book ∈ ΔIdea
o2p:Person ∈ ΔIdea
o2p:Publication ∈ ΔIdea
```

## 6.2. Именованные вещи

```text
ex:alice ∈ ΔThing
ex:bob ∈ ΔThing
ex:book123 ∈ ΔThing
```

## 6.3. Предикаты

Предикаты принадлежат `ΔRelation`:

```text
o2p:isInst ∈ ΔRelation
o2p:isSubC ∈ ΔRelation
o2p:hasAuthor ∈ ΔRelation
o2p:hasColorValue ∈ ΔRelation
```

## 6.4. Литералы

Литералы принадлежат `ΔData`:

```text
"red" ∈ ΔData
"white" ∈ ΔData
42 ∈ ΔData
```

# 7. Типы триплетов O2P

В RDF синтаксически каждый триплет имеет форму:

```text
<субъект> <предикат> <объект>
```

В O2P тип триплета определяется сортами субъекта, предиката и объекта.

Общая схема:

```text
<субъект из X> <предикат из Relation> <объект из Y>
```

где:

```text
X ∈ {Idea, Thing, Data}
Y ∈ {Idea, Thing, Data}
```

Но RDF накладывает ограничения:

- субъект — IRI или blank node;
- предикат — IRI;
- объект — IRI, blank node или literal.

## 7.1. Idea–Idea: отношения между идеями

```text
<Idea> <Idea–Idea relation> <Idea>
```

Пример:

```turtle
o2p:Book o2p:isSubC o2p:Publication .
```

Сигнатура:

```text
o2p:isSubC : ΔIdea × ΔIdea
```

Другие отношения:

```turtle
o2p:Book o2p:hasProperty o2p:hasColor .
o2p:Book o2p:hasMethod o2p:open .
o2p:Book o2p:isDisjointFrom o2p:Stone .
```

## 7.2. Idea–Idea с литералом

```text
<Idea> <Idea–Data relation> <Literal>
```

Пример:

```turtle
o2p:Book rdfs:label "Book"@en .
```

Это уже не логическое отношение между двумя идеями, а аннотация идеи данными.

Сигнатура:

```text
Idea × Data
```

## 7.3. Thing–Idea: вещь соответствует идее

```text
<Thing> <Thing–Idea relation> <Idea>
```

Пример:

```turtle
ex:alice o2p:isInst o2p:Person .
ex:bob o2p:isInst o2p:Person .
ex:book123 o2p:isInst o2p:Book .
```

Сигнатура:

```text
o2p:isInst : ΔThing × ΔIdea
```

Это основной мост между мирами.

## 7.4. Thing–Thing: отношения между вещами

```text
<Thing> <Thing–Thing relation> <Thing>
```

Примеры:

```turtle
ex:book123 o2p:hasAuthor ex:alice .
ex:alice o2p:knows ex:bob .
```

Сигнатуры:

```text
o2p:hasAuthor : ΔThing × ΔThing
o2p:knows     : ΔThing × ΔThing
```

## 7.5. Thing–Data: вещь имеет значение

```text
<Thing> <Thing–Data relation> <Literal>
```

Примеры:

```turtle
ex:book123 o2p:hasColorValue "red" .
ex:alice o2p:hasAgeValue "30"^^xsd:integer .
```

Сигнатуры:

```text
o2p:hasColorValue : ΔThing × ΔData
o2p:hasAgeValue   : ΔThing × ΔData
```

## 7.6. Idea–Data: метаданные идеи

```text
<Idea> <Idea–Data relation> <Literal>
```

Примеры:

```turtle
o2p:Book rdfs:label "Book"@en .
o2p:Book o2p:hasDefinition "A publication..."@en .
```

## 7.7. Idea–Thing: идея связана с образцом вещи

```text
<Idea> <Idea–Thing relation> <Thing>
```

Пример:

```turtle
o2p:Book o2p:hasPrototype ex:book123 .
```

Однако это отношение нужно отличать от `o2p:isInst`.

```text
ex:book123 o2p:isInst o2p:Book .
o2p:Book o2p:hasPrototype ex:book123 .
```

Первое утверждает принадлежность вещи категории. Второе утверждает, что конкретная вещь используется как образец идеи.

# 8. Все ли предикаты принадлежат миру идей?

Ваше предположение можно принять с уточнением:

> Все предикаты O2P являются терминами описания отношений, но не все они являются элементами мира идей в том же смысле, что `o2p:Book`.

Нужно различать:

```text
предикат как IRI
отношение как семантический объект
идея отношения
экземпляр отношения
```

Например:

```turtle
o2p:hasAuthor
```

может быть:

```text
IRI термина O2P
идея отношения
сигнатура Thing–Thing
```

Но в конкретном триплете:

```turtle
ex:book123 o2p:hasAuthor ex:alice .
```

`o2p:hasAuthor` выступает как предикат, а не как объект мира вещей.

Рекомендуемая модель:

```text
ΔRelation — множество отношений и предикатов
```

В него входят:

```text
o2p:isInst
o2p:isSubC
o2p:hasAuthor
o2p:hasColorValue
```

Далее можно связать отношение с миром идей:

```turtle
o2p:isInst o2p:describedByIdea o2p:InstanceRelation .
o2p:isSubC o2p:describedByIdea o2p:SubClassRelation .
```

Но не следует автоматически утверждать:

```text
все предикаты ∈ ΔIdea
```

Более точное утверждение:

```text
все предикаты имеют имена из словаря O2P;
их семантические типы задаются в метамодели O2P.
```

# 9. Заимствование терминов из существующих стандартов

## 9.1. `rdf:subject`, `rdf:predicate`, `rdf:object`

Эти термины можно сохранить только для технического описания RDF-тройки:

```text
RDF subject
RDF predicate
RDF object
```

Они не определяют миры O2P.

## 9.2. `rdfs:subClassOf`

Можно использовать как внешний RDF/RDFS-аналог, но в ядре O2P лучше использовать:

```turtle
o2p:isSubC
```

Причина:

```text
rdfs:subClassOf
```

имеет стандартную семантику классов RDF Schema, а O2P хочет отношение между идеями, а не стандартными RDF-классами.

Рекомендуется:

```turtle
o2p:isSubC rdfs:subPropertyOf rdfs:subClassOf .
```

Но это возможно только если `o2p:Book` и `o2p:Publication` также интерпретируются как RDFS-классы. В противном случае такое наследование будет семантически неуместным.

## 9.3. `owl:Class`

`owl:Class` можно использовать в адаптерном слое, но не в ядре O2P.

```text
owl:Class — стандартный OWL-класс
o2p:Idea — класс элементов мира идей O2P
```

Предлагаю:

```text
o2p:Idea — основной термин O2P
```

а `owl:Class` оставить для внешнего соответствия.

## 9.4. `owl:ObjectProperty`

В O2P нужен более точный набор аналогов:

```text
o2p:IdeaIdeaProperty
o2p:ThingIdeaProperty
o2p:ThingThingProperty
o2p:ThingDataProperty
o2p:IdeaDataProperty
```

Это не прямые замены `owl:ObjectProperty`, а специализированные типы отношений.

| O2P-термин | Прототип | Сходство | Отличие |
|---|---|---|---|
| `o2p:IdeaIdeaProperty` | `owl:ObjectProperty` | бинарное отношение | концы только в `ΔIdea` |
| `o2p:ThingIdeaProperty` | `owl:ObjectProperty` | связь двух ресурсов | субъект Thing, объект Idea |
| `o2p:ThingThingProperty` | `owl:ObjectProperty` | связь вещей | оба конца в `ΔThing` |
| `o2p:ThingDataProperty` | `owl:DatatypeProperty` | связь с literal | субъект Thing |
| `o2p:IdeaDataProperty` | `owl:DatatypeProperty` | связь с literal | субъект Idea |

## 9.5. Schema.org

Schema.org можно использовать как источник прикладных названий:

```turtle
schema:Person
schema:Book
schema:author
schema:name
schema:color
```

Но Schema.org не задаёт философское разделение `ΔIdea` и `ΔThing`. Его модель использует типы и свойства для структурированных данных; домены и диапазоны указывают, для каких типов свойства предназначены. [schema](https://schema.org/docs/datamodel.html)

Поэтому возможны два слоя:

```turtle
o2p:Person owl:equivalentClass schema:Person .
o2p:Book owl:equivalentClass schema:Book .
o2p:hasAuthor owl:equivalentProperty schema:author .
```

Но такие аксиомы будут корректны только в адаптерном слое и только после решения вопроса, как Schema.org-типы отображаются в O2P-идеи.

# 10. Онтология O2P

Ниже — первоначальная онтология O2P без `rdf:type` в утверждениях ядра.

Важно: Turtle сам по себе требует синтаксически корректных RDF-троек. Поэтому для описания того, что `o2p:Idea` является термином метамодели, можно использовать `owl:Class` только в технической декларативной части. В ядре предметных утверждений `rdf:type` не используется.

```turtle
@prefix o2p: <https://github.com/bpmbpm/ontology/o2p#> .
@prefix ex:  <https://example.org/> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs:<http://www.w3.org/2000/01/rdf-schema#> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
@prefix schema: <https://schema.org/> .

#################################################################
# Worlds
#################################################################

o2p:IdeaWorld
    rdfs:label "Мир идей"@ru .

o2p:ThingWorld
    rdfs:label "Мир вещей"@ru .

o2p:DataWorld
    rdfs:label "Мир данных"@ru .

#################################################################
# O2P meta-terms
#################################################################

o2p:Idea
    o2p:belongsToWorld o2p:IdeaWorld ;
    rdfs:label "Идея"@ru .

o2p:Thing
    o2p:belongsToWorld o2p:IdeaWorld ;
    rdfs:label "Вещь"@ru .

o2p:DataValue
    o2p:belongsToWorld o2p:IdeaWorld ;
    rdfs:label "Значение данных"@ru .

o2p:Relation
    o2p:belongsToWorld o2p:IdeaWorld ;
    rdfs:label "Отношение"@ru .

#################################################################
# World-membership predicates
#################################################################

o2p:belongsToWorld
    o2p:domain o2p:Idea ;
    o2p:range o2p:World ;
    rdfs:label "принадлежит миру"@ru .

o2p:World
    rdfs:label "Мир O2P"@ru .

o2p:isInst
    o2p:sourceSort o2p:Thing ;
    o2p:targetSort o2p:Idea ;
    rdfs:label "является экземпляром идеи"@ru .

o2p:isSubC
    o2p:sourceSort o2p:Idea ;
    o2p:targetSort o2p:Idea ;
    rdfs:label "является подклассом идеи"@ru .

#################################################################
# Idea–Idea relations
#################################################################

o2p:hasProperty
    o2p:sourceSort o2p:Idea ;
    o2p:targetSort o2p:Idea ;
    rdfs:label "имеет описание свойства"@ru .

o2p:hasMethod
    o2p:sourceSort o2p:Idea ;
    o2p:targetSort o2p:Idea ;
    rdfs:label "имеет описание метода"@ru .

o2p:isDisjointFrom
    o2p:sourceSort o2p:Idea ;
    o2p:targetSort o2p:Idea ;
    rdfs:label "не пересекается с"@ru .

#################################################################
# Thing–Thing relations
#################################################################

o2p:hasAuthor
    o2p:sourceSort o2p:Thing ;
    o2p:targetSort o2p:Thing ;
    rdfs:label "имеет автора"@ru .

o2p:knows
    o2p:sourceSort o2p:Thing ;
    o2p:targetSort o2p:Thing ;
    rdfs:label "знает"@ru .

#################################################################
# Thing–Data relations
#################################################################

o2p:hasColorValue
    o2p:sourceSort o2p:Thing ;
    o2p:targetSort o2p:DataValue ;
    rdfs:label "имеет значение цвета"@ru .

o2p:hasAgeValue
    o2p:sourceSort o2p:Thing ;
    o2p:targetSort o2p:DataValue ;
    rdfs:label "имеет значение возраста"@ru .

#################################################################
# Example ideas
#################################################################

o2p:Person
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:Book
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:Publication
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:ColorProperty
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:RedColorValue
    o2p:belongsToWorld o2p:IdeaWorld .

#################################################################
# Idea–Idea assertions
#################################################################

o2p:Book
    o2p:isSubC o2p:Publication ;
    o2p:hasProperty o2p:ColorProperty .

o2p:ColorProperty
    o2p:isSubC o2p:PropertyIdea .

o2p:PropertyIdea
    o2p:belongsToWorld o2p:IdeaWorld .
```

В этом варианте я сознательно не использую:

```turtle
o2p:Book rdf:type owl:Class .
```

и:

```turtle
ex:alice rdf:type o2p:Thing .
```

Ядро O2P использует отношения:

```turtle
o2p:belongsToWorld
o2p:isInst
o2p:isSubC
```

# 11. Пример с Алисой и Бобом

Ниже все конкретные индивиды находятся в `ex:`.

```turtle
@prefix o2p: <https://github.com/bpmbpm/ontology/o2p#> .
@prefix ex:  <https://example.org/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

#################################################################
# Ideas
#################################################################

o2p:Person
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:Book
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:Publication
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:Book
    o2p:isSubC o2p:Publication .

#################################################################
# Things
#################################################################

ex:alice
    o2p:belongsToWorld o2p:ThingWorld ;
    o2p:isInst o2p:Person ;
    o2p:knows ex:bob .

ex:bob
    o2p:belongsToWorld o2p:ThingWorld ;
    o2p:isInst o2p:Person ;
    o2p:knows ex:alice .

ex:book123
    o2p:belongsToWorld o2p:ThingWorld ;
    o2p:isInst o2p:Book ;
    o2p:hasAuthor ex:alice ;
    o2p:hasColorValue "red" .
```

Чтение:

```text
o2p:Person — идея человека.
o2p:Book — идея книги.
o2p:Publication — идея публикации.

ex:alice — конкретная вещь мира вещей.
ex:bob — конкретная вещь мира вещей.
ex:book123 — конкретная вещь мира вещей.

ex:alice является экземпляром идеи o2p:Person.
ex:bob является экземпляром идеи o2p:Person.
ex:book123 является экземпляром идеи o2p:Book.

o2p:Book является подкатегорией o2p:Publication.
ex:book123 имеет автора ex:alice.
ex:book123 имеет значение цвета "red".
```

# 12. Правила формирования триплетов

## Правило 1. Субъект

Субъект O2P-тройки должен быть:

```text
IRI идеи
IRI вещи
blank node
```

Литерал не может быть субъектом RDF-тройки.

## Правило 2. Предикат

Предикат должен быть IRI:

```text
o2p:isInst
o2p:isSubC
o2p:hasAuthor
o2p:hasColorValue
```

Литерал не может быть предикатом.

## Правило 3. Объект

Объект может быть:

```text
IRI идеи
IRI вещи
IRI мира
blank node
литерал
```

## Правило 4. Сигнатура

Каждый предикат должен иметь сигнатуру:

```text
domain × range
```

Например:

```text
o2p:isInst : Thing × Idea
o2p:isSubC : Idea × Idea
o2p:hasAuthor : Thing × Thing
o2p:hasColorValue : Thing × Data
```

## 12.1. Таблица типов триплетов

| Тип триплета | Форма | Пример |
|---|---|---|
| Idea–Idea | `<Idea> <IdeaRelation> <Idea>` | `o2p:Book o2p:isSubC o2p:Publication` |
| Idea–Data | `<Idea> <DataRelation> <Literal>` | `o2p:Book rdfs:label "Book"` |
| Thing–Idea | `<Thing> <ThingIdeaRelation> <Idea>` | `ex:alice o2p:isInst o2p:Person` |
| Thing–Thing | `<Thing> <ThingRelation> <Thing>` | `ex:book123 o2p:hasAuthor ex:alice` |
| Thing–Data | `<Thing> <DataRelation> <Literal>` | `ex:book123 o2p:hasColorValue "red"` |
| Idea–Thing | `<Idea> <IdeaThingRelation> <Thing>` | `o2p:Book o2p:hasPrototype ex:book123` |
| World declaration | `<Term> <WorldRelation> <World>` | `o2p:Book o2p:belongsToWorld o2p:IdeaWorld` |

## 12.2. Недопустимые триплеты

```turtle
ex:alice o2p:isSubC o2p:Person .
```

Недопустимо, потому что `o2p:isSubC` имеет тип:

```text
Idea × Idea
```

а `ex:alice` является вещью.

```turtle
o2p:Book o2p:isInst ex:book123 .
```

Недопустимо, потому что `o2p:isInst` имеет тип:

```text
Thing × Idea
```

а здесь порядок обратный.

```turtle
ex:book123 o2p:hasAuthor "Alice" .
```

Недопустимо, если `o2p:hasAuthor` имеет сигнатуру:

```text
Thing × Thing
```

В таком случае нужно использовать:

```turtle
ex:book123 o2p:hasAuthor ex:alice .
```

# 13. Отношение `o2p:isInst`

В O2P:

```turtle
ex:alice o2p:isInst o2p:Person .
```

означает:

```text
ex:alice ∈ ΔThing
o2p:Person ∈ ΔIdea
ex:alice ∈ ext(o2p:Person)
```

Не следует автоматически читать это как стандартное OWL:

```text
ex:alice rdf:type o2p:Person
```

Хотя по смыслу эти утверждения близки, `o2p:isInst` специально отражает двухсортную семантику O2P.

## 13.1. Наследование принадлежности

Если:

```turtle
o2p:Book o2p:isSubC o2p:Publication .
ex:book123 o2p:isInst o2p:Book .
```

то O2P-правило даёт:

```turtle
ex:book123 o2p:isInst o2p:Publication .
```

Формально:

```text
isSubC(A, B) ∧ isInst(x, A)
→ isInst(x, B)
```

## 13.2. Отсутствие обратного вывода

Из:

```turtle
ex:book123 o2p:isInst o2p:Publication .
```

не следует:

```turtle
ex:book123 o2p:isInst o2p:Book .
```

Если `Book` является подклассом `Publication`, направление только такое:

```text
Book → Publication
```

# 14. Отношение `o2p:isSubC`

```turtle
o2p:Book o2p:isSubC o2p:Publication .
```

Оба ресурса принадлежат миру идей:

```text
o2p:Book ∈ ΔIdea
o2p:Publication ∈ ΔIdea
```

Отношение наследует свойства стандартного `rdfs:subClassOf` только концептуально.

В O2P можно определить:

```text
o2p:isSubC rdfs:subPropertyOf rdfs:subClassOf .
```

Но делать это следует только в адаптерном OWL/RDFS-слое, поскольку стандартная семантика `rdfs:subClassOf` предполагает обычные RDF-классы, а не собственные двухсортные идеи O2P.

# 15. Что заимствовать, а что переименовать

| O2P-термин | Прототип | Решение |
|---|---|---|
| `o2p:Idea` | `owl:Class` | Не считать прямым эквивалентом; использовать как элемент мира идей |
| `o2p:Thing` | `owl:Thing` | Не считать эквивалентом; `owl:Thing` шире и относится к OWL object domain |
| `o2p:isInst` | `rdf:type` | Специализированный аналог Thing–Idea |
| `o2p:isSubC` | `rdfs:subClassOf` | Специализированный аналог Idea–Idea |
| `o2p:hasAuthor` | `schema:author` | Можно использовать как O2P-отношение Thing–Thing |
| `o2p:hasColorValue` | `schema:color` | Можно использовать как O2P-отношение Thing–Data |
| `o2p:hasProperty` | отсутствует точный аналог | Собственный термин O2P |
| `o2p:hasMethod` | отсутствует в OWL/RDFS | Собственный термин O2P |
| `o2p:belongsToWorld` | отсутствует | Собственный фундаментальный термин O2P |
| `o2p:IdeaWorld` | отсутствует | Собственный термин O2P |
| `o2p:ThingWorld` | отсутствует | Собственный термин O2P |

## 15.1. `o2p:Idea` не является `owl:Class`

Сходство:

```text
оба задают категорию или тип
оба могут иметь иерархию
оба могут быть связаны с экземплярами
```

Различие:

```text
owl:Class — стандартный OWL-класс, интерпретируемый как множество объектов OWL domain
o2p:Idea — элемент мира идей O2P
```

В O2P:

```text
o2p:Idea ∈ ΔIdea
```

а соответствующее множество вещей:

```text
ext(o2p:Idea) ⊆ ΔThing
```

## 15.2. `o2p:Thing` не является `owl:Thing`

Сходство:

```text
оба связаны с объектами
```

Различие:

```text
owl:Thing — универсальный класс всех объектов OWL object domain
o2p:Thing — концепт или сорт вещей мира O2P
```

В O2P:

```text
o2p:Thing ∈ ΔIdea
```

потому что это имя, описывающее мир вещей.

А сами вещи:

```text
ex:alice ∈ ΔThing
ex:bob ∈ ΔThing
```

# 16. Адаптер к OWL 2 DL

O2P может иметь отдельный адаптерный слой:

```turtle
@prefix o2p: <https://github.com/bpmbpm/ontology/o2p#> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
@prefix rdfs:<http://www.w3.org/2000/01/rdf-schema#> .

o2p:Person owl:equivalentClass o2p:PersonClass2 .
o2p:Book owl:equivalentClass o2p:BookClass2 .

o2p:isSubC rdfs:subPropertyOf rdfs:subClassOf .
```

Однако для полного соответствия O2P это потребует преобразования:

```text
o2p:isInst → rdf:type
o2p:isSubC → rdfs:subClassOf
o2p:hasAuthor → owl:ObjectProperty
o2p:hasColorValue → owl:DatatypeProperty
```

Такой адаптер полезен для стандартных OWL reasoner, но сам O2P-граф должен оставаться двухсортным.

# 17. Итоговая минимальная модель

```turtle
@prefix o2p: <https://github.com/bpmbpm/ontology/o2p#> .
@prefix ex:  <https://example.org/> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

# Идеи
o2p:Person
    o2p:belongsToWorld o2p:IdeaWorld .

o2p:Book
    o2p:belongsToWorld o2p:IdeaWorld ;
    o2p:isSubC o2p:Publication .

o2p:Publication
    o2p:belongsToWorld o2p:IdeaWorld .

# Вещи
ex:alice
    o2p:belongsToWorld o2p:ThingWorld ;
    o2p:isInst o2p:Person ;
    o2p:knows ex:bob .

ex:bob
    o2p:belongsToWorld o2p:ThingWorld ;
    o2p:isInst o2p:Person ;
    o2p:knows ex:alice .

ex:book123
    o2p:belongsToWorld o2p:ThingWorld ;
    o2p:isInst o2p:Book ;
    o2p:hasAuthor ex:alice ;
    o2p:hasColorValue "red" .
```

В этой модели:

```text
o2p:Person, o2p:Book, o2p:Publication — элементы o2p:.

ex:alice, ex:bob, ex:book123 — конкретные индивиды ex:.

o2p:isInst — отношение Thing–Idea.

o2p:isSubC — отношение Idea–Idea.

o2p:hasAuthor — отношение Thing–Thing.

o2p:hasColorValue — отношение Thing–Data.

rdf:type — не используется в ядре O2P.
```

Главное исправление по сравнению с предыдущей версией:

```turtle
ex:book123 o2p:hasColorValue "red" .
```

а не:

```turtle
o2p:book123 o2p:hasColorValue "red" .
```

`o2p:` содержит термины и отношения O2P. `ex:` содержит конкретные экземпляры и объекты примера. RDF предоставляет только синтаксис триплетов, а O2P добавляет сортировку миров, типы отношений и собственную двухсортную семантику. [w3](https://www.w3.org/TR/2013/CR-rdf11-concepts-20131105/)
